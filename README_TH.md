# Rin23 1.6.1 — หน้าสนับสนุนใหม่

- แถบกลับด้านบนคงที่ พร้อมแบนเนอร์กระทิงขนาดกระชับ
- รวมผู้รับและช่องทางไว้ในการ์ดเดียว ลดข้อความซ้ำ
- แท็บวางลิงก์ / รูป QR แสดงช่องทางทีละแบบ
- เมื่ออ่าน QR ได้ เปลี่ยนกลับมาดูลิงก์ก่อนกดยืนยัน ไม่มีการส่งซองอัตโนมัติ
- จัดระยะไอคอนปุ่มใหม่ แสดงสถานะระหว่างทำงานและประวัติเป็นการ์ด
- รองรับธีมมืดและสว่างตามการตั้งค่าเดิม ไม่แสดงเบอร์โทรผู้รับ
- กล่องยืนยัน การตรวจยอด การป้องกันซองซ้ำ และระบบรับซองเดิมไม่เปลี่ยน
- ทดสอบ compile, donation mock และ QR ในเครื่องแล้ว ยังไม่ได้ตรวจหน้าจอบนอุปกรณ์ Android จริง

# Rin23 1.6.0 — UI ใหม่ และธีมมืด / สว่าง

## สิ่งที่เปลี่ยน

- ตั้งค่า → รูปลักษณ์ → เลือกโหมดมืดหรือโหมดสว่าง มีสถานะบอกตัวเลือกปัจจุบันและจำค่าหลังปิดแอป
- สีพื้นผิว ตัวอักษร ปุ่ม ไอคอน กรอบ แถบระบบ และกล่องโต้ตอบเปลี่ยนตามธีม
- คงธีมมืดเป็นค่าเริ่มต้น ไม่ผูกตามธีมเครื่องในรุ่นนี้
- เมนูหมวด 5 ช่องขนาดเท่ากัน พร้อมไอคอนแอดออน โลก สกิน เท็กซ์เจอร์ และทั้งหมด
- ปรับการ์ด ระยะห่าง หัวเรื่อง รายละเอียดผลงาน แถบล่าง และจัดหน้าตั้งค่าเป็นกลุ่ม
- ไอคอนภาพใหม่ 6 แบบ: พระอาทิตย์ พระจันทร์ หน้าจอ โลก เสื้อ และช่องตาราง
- เปลี่ยนธีมแล้วจำแท็บ คำค้น ตัวกรอง และตำแหน่งเลื่อน โดยไม่สั่งปิด EngineService
- รูปแบนเนอร์โดเนทยังคงอยู่ และข้อความบนภาพมีสีเฉพาะที่อ่านได้ทั้งสองธีม
- เก็บหน้าดาวน์โหลด รายการโปรด การนำเข้า ZIP สุ่มผลงาน และระบบค้นหาเดิม

## ผลตรวจรุ่นนี้

- คอมไพล์ APK ด้วย Android SDK 35 และ Java 17 (release 8)
- ผ่าน host tests 11 ชุด รวม contrast ตัวอักษรหลัก/รอง ปุ่ม สถานะสำเร็จ และรายการเลือก ≥ 4.5:1 ทั้งสองธีม
- ตรวจลายเซ็นเดิมและ zip alignment; native engine คงเดิม
- ยังไม่ได้ทดสอบการวาดหน้าจอ การเปลี่ยนธีมระหว่างดาวน์โหลด หรือการเปิด Minecraft บนเครื่อง Android จริงในสภาพแวดล้อมนี้
- การทดสอบบริจาคใช้ mock ไม่ส่งซองเงินจริง และไม่แสดงหมายเลขผู้รับใน UI

## ลองบนมือถือ

1. ติดตั้ง APK ทับรุ่นเดิม แล้วเปิดตั้งค่า → รูปลักษณ์
2. สลับสว่าง/มืด ตรวจหน้าแรก รายการโปรด ดาวน์โหลด รายละเอียด และกล่องยืนยันลบ
3. ปิดเปิดแอปใหม่ ตรวจว่าธีมยังเป็นตัวเลือกเดิม
4. ทดลองเปลี่ยนธีมระหว่างโหลด ตรวจว่างานยังเดินต่อและปุ่มเปลี่ยนเป็น “เปิด” เมื่อบันทึกสำเร็จ
5. ตรวจตัวหนังสือและปุ่มที่ขนาดฟอนต์ของเครื่อง โดยเฉพาะจอขนาดเล็ก

## ประวัติ 1.5.0 — สุ่มผลงาน นำเข้า ZIP และปรับค้นหา

## ใช้งาน
- หน้าแรก: กด “สุ่มหาอะไรเล่น” แล้วเลือกหมวด จะเปิดรายละเอียดให้ดูก่อน ไม่ดาวน์โหลดอัตโนมัติ
- สุ่มจากหน้าแค็ตตาล็อก เลือกเฉพาะรายการที่มีสถานะพร้อมใช้งาน และพยายามไม่ซ้ำ 30 รายการล่าสุดในรอบเปิดแอป ไม่ใช่การรับรองความเข้ากันได้กับโลกหรือเกมทุกเวอร์ชัน
- ดาวน์โหลด: กด “นำเข้าไฟล์จากเครื่อง” เลือก .mcpack / .mcaddon / .zip จากตัวเลือกไฟล์ Android
- แอปจะตรวจ manifest และเตรียมสำเนาใน Download/rin23 จากนั้นใช้ “เปิดด้วย Minecraft” ตามเดิม ไม่แก้ต้นฉบับ
- รองรับ root manifest, โฟลเดอร์ครอบ, หลายแพ็กเป็นโฟลเดอร์ และ mcpack/mcaddon ที่อยู่ใน ZIP จะรวมแพ็กที่ตรวจพบทั้งหมด ไม่แสดงเลือกทีละแพ็กในรุ่นนี้
- จำกัดต้นฉบับ 256 MB, ข้อมูลที่อ่านคลายออก 512 MB รวมทั้งชั้นซ้อน, ไม่เกิน 12,000 รายการ และ 32 แพ็กต่อชั้น, ซ้อนสูงสุด 2 ชั้นภายใน
- ไม่รองรับ ZIP เข้ารหัส ZIP เสีย ZIP ทั่วไปที่ไม่มี manifest, โครงสร้าง manifest ซ้อนกันหรือโมดูลชนิดที่ไม่รองรับ
- ตรวจ CRC ชื่อซ้ำและเส้นทางไม่ถูกต้อง ไม่แตกเส้นทางจาก ZIP ลงระบบไฟล์ ประมวลผลใน worker
- ตรวจ SHA-256 ของสำเนาแพ็กก่อนบันทึก เพื่อไม่เพิ่มสำเนาที่นำเข้าแล้วและยังเปิดอ่านได้ ไม่เปรียบเทียบกับไฟล์ Marketplace ที่โหลดจากระบบเดิม

## ค้นหา
- ค่าเริ่มต้นสำหรับคำค้นเป็นลำดับตรงคำค้น ไม่บังคับเรียงตามวันที่
- เมนูตัวกรองเลือก “ใหม่ล่าสุด” หรือ “ตรงคำค้น” ได้
- รองรับ UUID ตรงผ่านรายละเอียด ไม่ส่ง UUID เป็นคำค้นชื่อ และยังเคารพหมวดที่เลือก
- ปรับช่องว่าง/อักขระซ่อน และ escape สัญลักษณ์ค้นหาให้เป็นตัวอักษร
- ไม่ส่งคำขอเก่าที่รอในคิวหลังมีคำค้นใหม่ พร้อมคงตัวป้องกันผลตอบกลับเก่าทับผลใหม่
- ไม่ได้เพิ่มการแปลคำค้นไทยเป็นชื่ออังกฤษหรือการแก้สะกดอัตโนมัติ

## ตรวจสอบ
ผ่าน host tests 10 ชุด รวม ZIP จริงหลายรูปแบบและคำขอค้นหาจำลอง พร้อม build/signature verification; ยังไม่ได้ทดสอบ Android/Minecraft หรือแค็ตตาล็อกจริงบนมือถือในสภาพแวดล้อมนี้
ติดตั้งทับรุ่นก่อนด้วยลายเซ็นเดิม ไม่ต้องถอนแอป

# Rin23 1.4.0 — รายการโปรดและค้นหาไฟล์

- แท็บรายการโปรด: เก็บ/นำออกด้วยไอคอนคั่นหน้าบนการ์ดหรือหน้ารายละเอียด
- รายการโปรดเก็บในเครื่อง เปิดแอปใหม่แล้วยังอยู่ เรียงรายการที่เก็บล่าสุดก่อน

- ช่องค้นหาในหน้าดาวน์โหลด: กรองชื่อไทย/อังกฤษทันที ไม่แยกตัวพิมพ์ ค้นหลายคำและนามสกุลได้
- แสดงจำนวนที่ค้นพบ พร้อมปุ่มล้างคำค้น ปุ่มเปิด Minecraft และลบไฟล์ทำงานกับรายการที่กรอง
- ไอคอนภาพใหม่ 4 รูป: คั่นหน้า/คั่นหน้าที่เก็บแล้ว/ค้นหาไฟล์/ล้างคำค้น
- คงธีมดำแดง แบนเนอร์บริจาค Discord การเปิดไฟล์และระบบป้องกันโหลดซ้ำ
- ติดตั้งทับ 1.3.0 ด้วยลายเซ็นเดิมได้ ไม่ต้องถอนแอป

ตรวจสอบ: ชุด host tests 8 ชุด รวมการเปิด store ใหม่/บันทึกไม่สำเร็จ/UUID ซ้ำ/ค้นภาษาไทย และคอมไพล์ APK ไม่ใช่การทดสอบบนมือถือจริง

# Rin23 1.2.1 — แก้ค้างหลังบันทึกและกันโหลดซ้ำ (versionCode 8)

- แก้เหตุการณ์จริง: native ส่ง Search prompt ขณะ MediaStore ยังบันทึกอยู่ รุ่น 1.2.0 return ออกก่อนจำว่า native จบแล้ว ทำให้บันทึกเสร็จแต่ session ไม่จบ
- DownloadSession.nativeReady() จำจบงานก่อนคืนว่ายังรอบันทึกหรือไม่ เมื่อ export ที่เหลือสำเร็จจะจบและแสดง ✓ ทันที ไม่ต้องรอ prompt อีกครั้ง
- กันโหลดซ้ำทั้งที่ปุ่มและ service.download ก่อนเริ่มงาน ถ้ามีรายการที่ complete อยู่จะไม่ส่งคำสั่งดาวน์โหลด
- กัน saved event ชื่อเดียวกันซ้ำในงานเดียว และก่อนสร้าง MediaStore row ตรวจไฟล์ UUID/ชื่อ/ขนาดเดิมที่เปิดได้เพื่อใช้ไฟล์เดิม
- ตอนเริ่มแอปตรวจประวัติกับ MediaStore: ต้องเผยแพร่แล้ว (IS_PENDING=0), ขนาดตรง และมีหัว ZIP จึงกู้ complete ของงาน 1.2.0 ที่ค้างได้ หากรู้ว่าบันทึกไม่ครบจริงจะไม่กู้เป็นสำเร็จ
- ยังไม่เปิดปุ่มดาวน์โหลดจนตรวจประวัติเดิมเสร็จ ป้องกันเผลอโหลดซ้ำในช่วงเริ่มแอป
- ไฟล์ซ้ำที่มีอยู่ก่อนอัปเดตไม่ได้ถูกลบอัตโนมัติ ไฟล์ก่อนรุ่น 1.2.0 ที่ไม่มี UUID ในประวัติจะไม่จับคู่ด้วยชื่ออย่างเดียว
- แยก canBrowse() ออกจากสถานะงานดาวน์โหลด ทำให้ค้นหา เลือกหมวด ดึงรีเฟรช และโหลดรายการต่อได้ระหว่างดาวน์โหลด งานค้นหาไม่เปลี่ยนสถานะ active download
- หลังบันทึกแล้วไม่เอาจำนวนไบต์ของไฟล์ network มาทับไบต์ของไฟล์ที่จัดแพ็กเสร็จ ป้องกันตัวเลขเช่น 527 KB / 504 KB
- ถ้า native ไม่ส่ง prompt หลัง export เสร็จ จะถาม prompt ด้วยบรรทัดว่างหนึ่งครั้ง ไม่ส่งคำสั่งดาวน์โหลดซ้ำ หากยังไม่ตอบให้ขึ้นข้อผิดพลาดที่จบได้แทนหมุนตลอด รายการยังดูได้
- ภาพ panorama ใต้คำอธิบายขยายความสูงให้เทียบกับช่องภาพปกติ รักษาอัตราส่วนและเลื่อนซ้าย–ขวาในภาพเดียว ไม่ย่อเป็นแถบเล็ก ภาพแนวตั้งยังแสดงเต็มความกว้างตามสัดส่วน
- เก็บความละเอียดภาพกว้างเพิ่มภายในขีดจำกัดหน่วยความจำ และจำตำแหน่ง pan เมื่อภาพอื่นโหลดตามมา
- คืนภาพ rin_cover เป็นพื้นหลังแบนเนอร์โดเนท พร้อม gradient ให้อ่านง่าย กดเปิดหน้าบริจาคได้ทั้งแผง เบอร์ยังไม่แสดงบน UI

## การตรวจ
เพิ่ม DownloadRegressionTest ใช้ transcript ของ Protocol จริงที่จบด้วย saved + Search prompt แล้วจำลอง export ที่ยังไม่เสร็จ ผ่านทั้งลำดับ prompt ก่อน/หลัง export, multipart ที่ล้มเหลว, การกู้ประวัติ, กันชื่อเหมือนต่าง UUID และความกว้าง panorama ที่เลื่อนได้
ผ่าน host tests เดิมและการสร้าง APK/ตรวจใบรับรองเดิม/16 KB alignment ไม่มีการทดสอบรับเงินจริง
ยังไม่ได้ติดตั้งทดสอบ gesture หรือ native download บน Android จริงในเครื่องพัฒนา ต้องตรวจผลบนมือถือของผู้ใช้

# Rin23 1.2.0 — หน้าแรกและรายละเอียดใหม่ (versionCode 7)

## ที่เปลี่ยนในรุ่นนี้

# Rin23 1.1.2 — บริจาคในแอปโดยตรง (versionCode 5)

## ใช้งาน
ติดตั้ง APK ทับรุ่นเดิม กดปุ่มหัวใจด้านบน หรือ ตั้งค่า → สนับสนุน Rin23 ด้วยซองอั่งเปา

- วางลิงก์ซองอั่งเปา หรือเลือกรูป QR ของซอง
- อ่าน QR ในเครื่องด้วย ZXing ไม่อัปโหลดรูป และไม่ขอสิทธิ์กล้อง/เข้าถึงรูปทั้งเครื่อง
- ใช้ตัวเลือกไฟล์ของ Android เฉพาะรูปที่ผู้ใช้เลือก รูปต้องมี QR ซองเดียว
- QR พร้อมเพย์/QR ทั่วไปที่ไม่ใช่ลิงก์ซอง TrueMoney ใช้ไม่ได้
- แสดงผู้รับและคำยืนยันชัดเจน กดยืนยันแล้วจึงส่งคำขอรับเงินจริงจากซอง
- ผู้รับล็อกเป็นเบอร์ที่เจ้าของแจ้ง ไม่มีช่องเปลี่ยนเบอร์ปลายทาง
- แอปใช้ฟรี การบริจาคไม่เพิ่ม/ปลดล็อกฟีเจอร์

## วิธีเชื่อมโดยไม่มีโฮสต์
แปลง flow ของ rin-topup ที่เจ้าของให้มาเป็น Java Android ไม่ใช่รัน npm/Node.js ใน APK
มือถือผู้บริจาคเชื่อม HTTPS ไป gift.truemoney.com โดยตรง เฉพาะเมื่อผู้ใช้ยืนยัน
ไม่ต้องมี Node.js, Termux, เซิร์ฟเวอร์กลาง หรือเปิดเครื่องของเจ้าของค้างไว้
ใช้ Android TLS/HTTPS ตามปกติ ไม่ปลอมตัวเป็น browser ไม่พยายามหลบการบล็อก และไม่ลอง transport อื่นเมื่อถูกปฏิเสธ
การรับเงินจริงขึ้นกับการอนุญาตของ TrueMoney และเครือข่ายมือถือ หาก HTTP 401/403 จะแจ้งปฏิเสธ ไม่มีการเปลี่ยนเครื่องมือหรือ retry อัตโนมัติ

## ความถูกต้องของเงินและสถานะ
- ยืนยัน success จาก status.code=SUCCESS พร้อม data.my_ticket.amount_baht ที่ตรวจแล้วเท่านั้น ไม่ถือ HTTP 200 อย่างเดียวเป็นความสำเร็จ
- ใช้ BigDecimal และจำนวนเต็มสตางค์ ไม่ใช้ float คำนวณยอด
- SQLite บันทึก checking ก่อนตรวจ provider และ submitted ก่อนเปิดคำขอรับซอง
- ถ้าบันทึกก่อนส่งไม่ได้ จะไม่ส่ง POST
- ไม่ส่ง POST ซ้ำอัตโนมัติ หากขาดการเชื่อมต่อหลัง checkpoint หรือผลผิดรูปแบบ จะขึ้น unknown/ยังยืนยันผลไม่ได้ ไม่ขึ้นรับเงินสำเร็จ
- หลัง process ถูกปิด: checking ที่ยังไม่ส่งเปลี่ยนเป็น not_sent; submitted เปลี่ยนเป็น unknown และไม่ส่งซ้ำ
- ป้องกันส่งซ้ำจากประวัติบนมือถือเครื่องนี้ การถอนแอป/ล้างข้อมูลหรือเปลี่ยนเครื่องทำให้ประวัติในเครื่องหาย กฎรับซองซ้ำข้ามเครื่องยังขึ้นกับระบบ TrueMoney
- ประวัติไม่เก็บรหัสซอง/ลิงก์ดิบ/รูป เก็บ hash, สถานะ, ยอดที่ยืนยัน, เวลา และเลขรายการในเครื่อง
- เลขรายการในเครื่องไม่ใช่เลขธุรกรรมยืนยันจาก TrueMoney
- ไม่ขอรหัสผ่านบัญชีหรือ OTP

## การทดสอบรุ่นนี้
ผ่าน Java compile, DEX/APK build, signing/alignment และ host tests:
- เลขผู้รับตายตัว ลิงก์ปลอม ยอดผิดรูปแบบ และการยืนยันก่อนใช้ network
- จุดบันทึกก่อน POST และไม่ส่งหากจุดบันทึกล้มเหลว
- ปิดปรับปรุง/HTTP403/timeout/คำตอบที่ยืนยันไม่ได้ ไม่มี retry อัตโนมัติ
- สร้าง QR จริงใน test แล้ว decode ทั้งภาพปกติ หมุน กลับสี ปฏิเสธ QR พร้อมเพย์/ภาพว่าง/หลายซอง
- regression protocol/catalog/infinite feed/transfer meter เดิม

**ยังไม่มี Android device/emulator ในเครื่องพัฒนา และยังไม่ได้ทดสอบรับเงินจริงบนมือถือ จึงไม่รับรองว่า HTTPS จากมือถือจะได้รับอนุญาตจาก TrueMoney จนกว่าจะทดลองจริง**
การทดสอบทั้งหมดใช้ข้อมูลจำลอง ไม่ได้ส่ง POST รับซองเงินจริง

Dependency QR ถูกบรรจุใน deps/zxing-core-3.5.3.jar พร้อม license ใน third-party/ และ APK assets ไม่ต้องดาวน์โหลด dependency ขณะใช้แอป

รุ่น 1.0.0 ได้รับการยืนยันจากผู้ใช้ว่าเปิดใช้งานบนเครื่องได้แล้ว; ข้อนี้ไม่ใช่การรับรองทุกฟีเจอร์ในรุ่นใหม่

## สำหรับผู้ติดตั้ง
1. ติดตั้ง Rin23-v1.1.0-arm64.apk บน Android 10 ขึ้นไป (มือถือ ARM64)
2. Android อาจให้อนุญาตติดตั้งจากแหล่งที่ดาวน์โหลดไฟล์ครั้งแรก
3. เปิด Rin23 รออัปเดตฐานข้อมูลและเชื่อมต่อแค็ตตาล็อก
4. พิมพ์ชื่อ เลือกหมวด กดค้นหา แล้วกดดาวน์โหลดจากรายการ
5. ไฟล์สำเร็จจะถูกบันทึกลง Download/rin23 ด้วย MediaStore โดยไม่ต้องติดตั้ง Termux หรือพิมพ์คำสั่ง
6. หน้าไฟล์ของฉันมีปุ่มเปิดด้วย Minecraft และปุ่มเปิดโฟลเดอร์
7. หากมีหลายรุ่น ให้เลือกรุ่นที่ต้องการในหน้าต่างของแอป
8. เมนู ••• > ปิดแอป จะหยุดโปรแกรมและงานเบื้องหลัง

ต้องมีอินเทอร์เน็ตเพื่อค้นหาและดาวน์โหลด การมีฐานคีย์สำรองไม่ได้ทำให้แค็ตตาล็อกใช้งานออฟไลน์ได้
เมื่อถอนแอป ข้อมูลภายในและประวัติจะถูกลบ แต่ไฟล์ที่ส่งออกสำเร็จใน Download/rin23 ยังคงอยู่
แอปใช้ foreground service เพื่อให้งานดำเนินต่อเมื่อสลับแอป แต่ Android/ผู้ผลิตเครื่องยังอาจหยุดงานได้
หากไม่มี Minecraft หรือไม่มีแอปรองรับ ให้เปิดไฟล์จากแอปจัดการไฟล์แทน

## ขอบเขตการทดสอบ
- คอมไพล์ Java และสร้าง APK ด้วย Android SDK 35
- ตรวจการอ่านข้อความโปรแกรมแบบทั้งก้อนและทีละตัวอักษร รวม ANSI แบ่งข้ามก้อน
- ตรวจชื่อที่มีวงเล็บเหลี่ยม ชื่อผู้สร้าง หมายเลขหน้า สถานะคีย์ การเลือกรุ่น และชื่อไฟล์สำเร็จ
- ทดสอบ Java AES-CBC/PKCS7 กับไฟล์ฐานสดจริงและตรวจ TSV 10,520 แถว
- ตรวจ ELF ARM64 และ alignment 16 KB ของตัวโปรแกรมที่ฝัง
- ตรวจ zipalign และลายเซ็น APK
- ยังไม่ได้ติดตั้ง/เปิด UI/ทดลองดาวน์โหลดและส่งออกผ่าน MediaStore บนมือถือจริง
  จึงเป็นรุ่นทดสอบ ไม่ใช่การรับรองว่าทำงานครบทุกยี่ห้อ

## สถาปัตยกรรม
Native Android Java UI + foreground service + bundled ARM64 executable
ไม่มีเว็บเซิร์ฟเวอร์ ไม่มี Termux ไม่มีการดาวน์โหลด executable เพิ่มตอนใช้งาน
ตัวโปรแกรมดั้งเดิมถูกบรรจุใน lib/arm64-v8a/librinengine.so และเรียกผ่าน nativeLibraryDir
manifest ตั้ง extractNativeLibs=true เพื่อให้ Android ติดตั้งไฟล์ executable ไว้ในตำแหน่งที่เหมาะสม
Android UI ควบคุมคำสั่งผ่าน stdin/stdout โดยใช้ ProcessBuilder โดยตรง ไม่มี shell
UI เป็นภาษาไทย ส่วนเครื่องมือพื้นฐานยังเป็น Rustcoin 1.2.0 ที่ผู้ใช้แนบมา
ตัวเชื่อมอ่าน protocol ของรุ่นนี้โดยเฉพาะ การอัปเดต engine ต้องรันทดสอบ Protocol ใหม่

KeySync ใช้ค่าปลายทางและกุญแจที่ผู้ใช้ให้มา ตรวจ padding/UTF-8/หัวตาราง/จำนวนคอลัมน์
และเขียน cache แบบ AtomicFile; ถ้าอัปเดตล้มเหลวใช้ cache ที่ตรวจแล้ว
เครื่องมือพื้นฐานยังตรวจคีย์ของตัวเองอีกครั้งหลังเริ่มทำงาน
ข้อมูลบัญชี guest/token เก็บเฉพาะ app-private storage; allowBackup=false; ไม่บันทึก stdout ดิบลง log
MediaStore เพิ่มไฟล์แบบ IS_PENDING แล้วเปิดเผยเมื่อคัดลอกครบเท่านั้น

## คอมไพล์ (เครื่องพัฒนา Linux/macOS ที่มี Java 17, Android SDK)
ต้องติดตั้ง platforms;android-35 และ build-tools;35.0.0 และมี zip

    RIN23_ANDROID_SDK=/path/to/android-sdk bash build-apk.sh

ผลลัพธ์ unsigned: build/aligned.apk
การเซ็นใช้ keystore ของเจ้าของแอปเท่านั้น (ไม่แนบในซอร์สสาธารณะ):

    export RIN23_KEYSTORE=/private/rin23-signing.p12
    export RIN23_STORE_PASSWORD='รหัสของเจ้าของแอป'
    RIN23_ANDROID_SDK=/path/to/android-sdk bash build-apk.sh

ผลลัพธ์ signed: build/Rin23-v1.1.1-UI2-arm64.apk
สร้างรุ่นใหม่ให้เพิ่ม version-code ใน build-apk.sh และใช้คีย์เดิมเพื่ออัปเดตทับแอปเดิม
ห้ามเผยแพร่ไฟล์สำรองคีย์เซ็นแอป
